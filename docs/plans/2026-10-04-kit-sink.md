# kit-sink (Phase 0) Implementation Plan

**Goal:** `/kit sink` opens a Pane with every cc-kit catalog candidate drawn on mock data (live where a collector exists), so components can be judged and picked.

**Architecture:** Pure components `(el, props) => tree` in `hooks/kit/*.tsx`, imported relatively by `hooks/register.tsx`. Tabs are Buttons that write a `$.state` atom. Live collectors: `tool.call` (timeline, file touches, subagents), `turn.complete` → `$.session.usage` (tokens, context).

**Spec:** `docs/specs/2026-10-04-cc-kit-v1-design.md` (Phase 0)

## Global Constraints
- Elements used: only those every surface has (Box, Text, Button, Code, Markdown), so terminal and desktop both draw it.
- The Pane is opened only from a command (`/kit sink`, aliased as `/kit-sink`), never unasked.
- Width comes from `e.props.bodyColumns`.

## Review Focus
1. Narrow Pane (<50 cols): every component still renders and nothing overflows.
2. No live data yet (fresh session): observability shows mock data, labelled "mock".
3. Tool call that errors: the timeline marks it red and the session continues.
4. Hot reload mid-session: the selected tab and collected calls survive (they live in `$.state`).
5. Desktop surface: the same tree validates.

## Tasks
1. Scaffold the manifest, hooks.json and types contract → `claude plugin validate` passes.
2. Foundations: `kit/foundations.ts` (tones, bar, spark, truncate, pad, formatters).
3. Data group: Sparkline, Gauge, StatTile, BarList, Heatmap.
4. Observability group plus collectors.
5. Mocks for groups 3–6.
6. Pane with tabs, the `/kit` command and a first-run toast.
7. Tests looping over terminal and desktop; `claude plugin test` green; mirror into `~/Code/cc-kit/mods/kit-sink`.
